# verify/fixtures — independent golden expectations

These fixtures are **checker-owned** and were derived by hand from the authoritative Qt6 C++
reference app at `/home/bismillah/QuestaLauncher` (not from the writers' implementation and not from
`TEMPLATES.md`, which was only used to cross-check line references).

## Layout

```
projects/            input fixture projects (copied to a temp dir per run)
  basic/             alpha.sv, beta.sv, gamma_tb.sv      (alpha-ordered, one testbench)
  exclusions/        a.sv, b.sv, c_tb.sv                 (b.sv excluded by the caller)
  priority/          x.sv, y.sv, z_tb.sv                 (custom Questa order exercised)
  gowin-ports/       top.sv                              (port-parser edge cases)
expected/            golden generated files (timestamp literal 2026-10-30T16:45:12)
  basic/run.do              Questa run.do, GUI mode
  basic/run-cli.do          Questa run.do, preserved CLI variant (no add-wave, quit -f)
  basic/run-with-libs.do    Questa run.do with one project dependency
  basic/quartus/            .qpf / .qsf / .sdc
  basic/gowin/              .f / .gprj / .cst (built from beta.sv ports)
  exclusions/               same three generators with b.sv excluded
  priority/                 Questa custom order y,z_tb,x; Quartus/Gowin deterministic active order
  gowin-ports/              ports.json, CST templates (default/override/empty ports)
```

**Lead-approved determinism decision:** `QDir::entryList` order is filesystem-dependent, so the port
standardises on deterministic sorted basenames: `allSvFiles` alphabetical, default compile order =
non-`_tb.sv` (alpha) then `_tb.sv` (alpha). Fixtures are therefore insensitive to FS order while still
exercising the Qt split/order rules. For Questa the custom compile order (if set) wins verbatim; Quartus
and Gowin consume the deterministic active list (Qt `launchForQuartus`/`launchForGowin` use `activeFiles`).

**Byte-level rules:** LF newlines only; `timestamp` is an explicit parameter (local `YYYY-MM-DDTHH:MM:SS`);
`tbModule` = testbench filename with all `".sv"` substrings removed; `.cst` content is passed through
verbatim by the generator (the dialog produces it, exactly as in Qt `mainwindow.cpp:788-796`).

**Ordering of `expected/priority/run.do`:** files `y.sv z_tb.sv x.sv` — Qt honours `m_customOrder`
verbatim in `generateRunDo` (`mainwindow.cpp:628-631`).

Regenerate not required — the goldens are static and must be changed only with a new citation from the
Qt source. `verify/run-checks.js` compares with trailing-newline normalisation only.
